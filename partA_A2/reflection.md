# 느낀 점 및 경험한 성과

## 경험한 성과

이번 해커톤에서 저희 팀 soara는 단순한 개념 증명(PoC)을 넘어, 실제 위협 탐지부터 AI 분석, 사람의 승인, 자동 차단, 실시간 시각화까지 전 과정이 실제로 동작하는 엔드투엔드 파이프라인을 완성했습니다.

Kinesis로 실시간 트래픽을 스트리밍하고, Lambda가 슬라이딩 윈도우 방식으로 위협 점수를 계산해 DynamoDB와 S3에 기록하는 탐지 파이프라인을 구축했고, 여기에 그치지 않고 Step Functions의 `waitForTaskToken` 패턴을 활용해 실제로 사람이 승인해야만 차단이 실행되는 Human-in-the-Loop 구조를 구현했습니다. 여기에 더해 Amazon Bedrock AgentCore와 Strands Agent, MCP 프로토콜을 활용한 AI 에이전트를 통합해서, 규칙 기반 점수뿐 아니라 사람이 읽을 수 있는 자연어 판단 근거까지 제공하는 설명 가능한 탐지 시스템을 만들었습니다. 마지막으로 이 모든 과정을 한눈에 볼 수 있는 실시간 대시보드까지 완성해서, 탐지부터 대응까지의 전체 흐름을 시연 가능한 형태로 보여줄 수 있었습니다.

특히 인상 깊었던 성과는, 시연 직전에 발견한 AWS 계정 차원의 공개 엔드포인트 차단 제약을 우회해서 대시보드를 끝까지 살려낸 부분입니다. Lambda Function URL과 API Gateway 둘 다 익명 호출이 계정 정책으로 막혀 있다는 걸 직접 curl로 재현해서 확인했고, 결국 CloudShell의 인증된 세션에서 직접 실행하는 로컬 서버 + 터널링 방식으로 전환해서 문제를 해결했습니다. 정해진 방법이 막혔을 때 근본 원인을 정확히 진단하고 다른 경로를 찾아낸 경험이었습니다.

## 느낀 점

가장 크게 느낀 건, 실제로 동작하는 시스템을 만드는 것과 그걸 "발표 가능한 상태"로 만드는 것은 완전히 다른 작업이라는 점이었습니다. 코드 로직 자체는 일찍 완성됐지만, Cognito 인증 스코프 오류, CloudShell 디스크 용량 초과, Kinesis 컨슈머 백로그 지연, Lambda 공개 호출 계정 제약, UTF-8 디코딩 버그처럼 예상 못 한 인프라·환경 이슈들이 계속 튀어나왔고, 이런 것들을 하나씩 원인을 좁혀가며 해결하는 과정 자체가 실무에 훨씬 가까운 경험이었습니다.

또한 시간이 한정된 해커톤 환경에서 "무엇을 더 만들지"와 "무엇을 포기할지"를 계속 판단해야 했던 것도 배운 점입니다. 초반에는 시간 부족을 우려해 Human-in-the-Loop 승인 플로우(Part C)를 미뤘지만, 이후 시간 여유가 생기자 이를 다시 추가하기로 결정했고, 프론트엔드 대시보드 역시 "다른 팀과의 차별화 요소가 필요하다"는 판단 아래 뒤늦게 추가했습니다. 결과적으로 이 두 가지 결정이 프로젝트의 완성도와 차별성을 크게 끌어올렸습니다.

마지막으로, 왜 완전 자동화가 항상 정답은 아닌지를 이번 프로젝트를 통해 체감했습니다. AI가 위협을 정확히 판단하더라도, 실제 서비스에 영향을 주는 액션(차단)까지 AI가 독단적으로 실행하게 두면 오탐 하나로 큰 사고가 날 수 있습니다. 저희가 설계한 "AI는 판단과 설명까지, 최종 실행은 반드시 사람이" 라는 구조는 기술적 구현을 넘어서, 실제 보안 운영에서 중요하게 여겨지는 철학을 그대로 반영한 결과라고 생각합니다.
